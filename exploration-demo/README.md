# MAP001 單場景行走驗證台

以已核對的 MAP001 室內背景、玩家原始整數座標及固定鏡頭，驗證指定區域移動與碰撞。玩家只顯示位置、朝向與形狀框；本輪沒有角色動畫、NPC、對話、戰鬥或存讀檔。背景依來源 NBG1、NBG0 圖層順序顯示，不宣稱包含原作精靈及遮擋合成。

視窗以 1920×1080 邏輯排版適應 1080p、1440p、4K，背景保持 320×224 比例並採最近鄰放大。右側 17 欄以十六進位顯示「核心 / 原作」；自由行走沒有原作對照值。青色格表示來源軌跡實際查詢過的 108 格；紅格另外標示 `0x80`。這些是診斷資料，不能把單一旗標視為全遊戲通用障礙。

## 操作

| 操作 | 按鍵或按鈕 |
| --- | --- |
| 四方向移動 | 方向鍵、WASD |
| 暫停／恢復 | Space、播放／暫停 |
| 單步 | `.`、單步（自動暫停） |
| 重設當前模式起點 | R、重設 |
| 顯示／隱藏格網及軌跡 | F1、疊圖 |
| 切換原作對照 | 右上模式及路線選單；1～4 直接選路線 |

多方向同按會保留整個狀態，連待修正位移也不消耗；方向鍵和相同方向的 WASD 屬同一方向。放開單方向後仍按原作規則消耗已排定的修正量。視窗失焦會清除按住狀態。嘗試查詢未驗證格時，整次更新不套用並顯示「測試邊界」，不增加虛構牆壁。

原作對照提供四組已捕捉路線：四方向接觸與持續壓牆、轉角、空地、放開按鍵。切換路線會重設並暫停；按播放或單步開始。核心從起點及原作輸入字推進，後續原作座標只供比較，不回填核心。每次更新比較全部 17 欄；差異欄以紅色顯示，累計值是有差異的更新次數。金線和圓圈表示原作軌跡與當前原作位置，青線表示核心行走路徑。

## 資料及啟動

Windows ZIP 完整解壓後，直接執行 `MAP001-Walk.exe`，不需要 Godot 編輯器。請保留同目錄的 `.pck` 與 `scene` 資料夾。

開發資料包預設位於 `generated/scene`；獨立執行檔從同目錄的 `scene` 載入。可傳 `--scene-package=絕對路徑` 指向相同核准資料包。來源、必需檔案、尺寸或雜湊不符會拒絕啟動，不會改用示意地圖。含來源素材的資料包與 Windows ZIP 僅留本地。

使用已鎖定的 Godot 4.7.2 Compatibility renderer。專案沒有向系統安裝任何工具或修改原作存檔；資料包生成、來源驗證及 Windows 匯出由父專案工具負責。

## 自動驗證入口

在 Godot 命令列的 `--` 後附參數：

```
--qa-output=G:/absolute/path/1080.png --qa-size=1920x1080
--qa-output=G:/absolute/path/soak.json --qa-size=3840x2160 --qa-soak-seconds=600
```

截圖模式暖機後輸出 PNG 及同名 `.json` 報告並退出。可用 `--qa-report=路徑` 指定報告位置。輸出目錄須先存在。長測試預設暖機 15 秒，可用 `--qa-warmup-seconds=N` 調整；暖機後持續重播全部四組路線，直到測量秒數完成並退出。GPU 實際像素在計時前、計時後核對；測量中逐幀檢查視窗尺寸及縮放設定，不讀圖也不存截圖。尺寸漂移會明確失敗。

報告保存逐幀單調時鐘間隔、平均 FPS、P95、最大值、超過 50 ms 的時點、每秒 Godot 記憶體／節點數，以及前後各 20% 取樣的中位數。引擎進入至第一張畫面與尺寸穩定確認分開記錄；穩定確認包含 250 ms 等待，不等同首次呈現或作業系統冷快取。Godot 記憶體是引擎配置器數值；程序記憶體和顯存由外部 QA 工具另行記錄。功能結果與效能目標分開列示，短測試不代表 10 分鐘驗收。

UI 整合測試使用 `--headless --path exploration-demo --script res://tests/test_ui.gd`；使用真正鍵盤／滑鼠事件及已核准資料包，驗證暫停、單步、重設、多方向、測試邊界、完整路線及 30／60／120 FPS 時間分割一致。另以 `--script res://tests/fps.gd -- --fps=30`（另跑 60、120）測試實際引擎迴圈的四組完整重播；可加 `--output=絕對路徑` 保存報告。無畫面測試不能替代三解析度實際截圖及渲染效能測試。

本驗證範圍仍不涵蓋完整地圖、鏡頭捲動、其他形狀與控制模式、事件或原作戰鬥，Stage B 不因此整體通過。
