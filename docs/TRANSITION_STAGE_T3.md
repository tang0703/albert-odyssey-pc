# T3：落點來源、行走及畫面驗證

本階段來源驗證通過，尚非 Windows 候選版交付；效能未驗收，未執行負載或效能測試。

- 沿用正常取得及裝備流程，`landing-corridor` 三次各 1,588 個模擬畫面，所有採樣 payload 相同；每次 860,892 項連續模型比較零差異。
- 開放範圍取 95 個實際查表格的聯集，限制於首次可控視窗 x=640..959、y=1816..2039。查表格不等於可走圖塊；碰撞形狀可能同時查多格。只驗證落點右側通道，未聲稱整間目的地完成。
- Godot 四條完整路線共 80,407 項比較通過，包括重設與過期／重複載入回應。
- 額外逐幀繪圖採樣與一般觀察器的 431 份 RAM、圖像及 VRAM payload 一致。443 次繪製及 442 個顯示畫面通過，共 31,629,202 個畫面像素零未解釋差異。包含首次可見背景及淡入；僅省略已明列的原作影子，沒有排除文字框區域。
- 原作先清空 VDP1；首個可見新背景尚無人物。第一個人物畫面因初始化等待相隔三個模擬畫面，後續穩定顯示延遲為兩次更新。RGB offset 依前一個完成畫面的暫存器取樣，與人物／鏡頭延遲分開，不沿用舊房間三更新佇列。
- 解碼八個物件及一個必要角色，共 16 張來源影格；新物件 6／7 是椅子，沒有沿用舊版省略規則。離屏物件仍參與排序，僅按原作逐片段裁除規則不提交繪製。
- 原作裁除範圍為 X=0..319、Y=0..256（含端點），不是最終 224 線畫面。物件例程 `06098F82`，角色例程 `06097400..06097AEC`；整份來源及例程雜湊均核對。
- 回程樓梯與左側劇情邊界各三次重播相同。回程在 (904,1896) 提出場景提交；左側 (880,1936) 進入腳本 0x2C17。本輪皆為測試邊界，不執行其後續事件或載入第三場景。未納入查表聯集的位置可能更早遭驗證邊界拒絕，不把這種邊界標為原作牆壁。

初版 `landing-coverage` 路線失敗，原因是原作放開方向後仍可能執行位置修正；最初的路線規劃未包含該修正。保留完整失敗證據；其中查表範圍未核准。重複採樣在確認失敗後停止，未把不完整輸出當成證據。
