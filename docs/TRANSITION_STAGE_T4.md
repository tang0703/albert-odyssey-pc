# T4：單向轉場流程整合

獨立入口為 `exploration-demo/transition_main.tscn`。既有裝備入口仍停在原來的轉場提交邊界；舊七包未改動。

完整流程已通過功能驗證：正常取得／裝備、原作淡出、具名載入回應、初始化、淡入、恢復控制及落點行走。新場景先顯示清空人物層的背景，再依已驗證的兩更新延遲顯示人物與物件。顏色 offset 獨立套用，沒有改用通用黑色透明遮罩近似原作加減色。

素材在啟動時預載，場景提交只消費具名回應。每次 R 重設增加 generation、清空回應佇列、停止音訊並還原原房所有狀態；過期／重複回應遭拒。轉場期間不接受移動、互動或裝備，仍按住的按鍵必須放開再按。失焦暫停並隔離未放開的按鍵。

實測結果：

- 獨立 Godot 核心：80,419 項比較及狀態防護通過。
- UI：三外觀、四條完整來源路線共 10,965 次更新，70 項功能檢查通過。
- 經 Viewport 實際派送的鍵盤／滑鼠事件：15 項通過，包括裝備／卸下、關閉與目的地重設。
- Compatibility 實際 GPU **圖像正確性**：13 個短程代表畫面全部與來源逐像素一致（既有影子除外），包含首個可見無人物背景、第一個人物畫面、淡入、轉向、接牆與鏡頭位移。由起點輸入連續推進，未注入後續角色狀態。
- 30／60／120 FPS 僅為合成時間分割；未量測實際 GPU FPS、負載、記憶體長期增長或效能基準。

本地證據為 `reports/transition/t4-core.json`、`t4-ui.json`、`t4-input.json`、`t4-gpu.json`。下一階段 T5：可用來源回歸、三解析度短程截圖、獨立 Windows 匯出、ZIP 逐檔及解壓啟動驗證。
