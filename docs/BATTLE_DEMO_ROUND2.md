## S1 驗證與回歸缺口

戰鬥核心原有 173 項斷言通過。動畫元件 39 項、計量器及節點診斷 26 項、封裝 8 項及 QA 門檻 16 項檢查通過。演出 UI 正式素材整合後 417 項通過，包含實際完成訊號、按住 Enter、命中後暫停、勝敗與再戰；另有設定 5 項及 6 組 FPS／速度一致性驗證。

## 動畫與演出契約

`fighter.configure()` 在開始前驗證並載入所有必要動作。每動作使用 `frames`、`durations`、`loop`，攻擊另有零起算 `hit_frame`。角色保存正規化 `anchor`、`scale`、`default_facing`。缺圖、空動作、錯誤時長與命中點會禁止開始，不改用簡易人物掩蓋。

核心只結算一次。UI 保存獨立顯示快照，在命中點顯示 HP／MP、飄字與音效，再等候受傷／倒下完成才解鎖。倒下保留末格，待機循環；防禦及藥水使用待機與特效。普通攻擊及重擊共享攻擊動作，命中特效大小與色彩不同。

```powershell

```

效能程序暖機 15 秒後開始計量；計量期間不存截圖、不讀回 GPU 圖片、不並行其他驗證。記錄平均／P95／最高影格時間與超過 50 ms 時點、每秒程序記憶體及每 10 秒 Godot 節點／靜態記憶體／渲染器顯存。Godot 顯存計數不是整張 GPU 的全部配置量。

ZIP 審核採核心資源與核准圖片 manifest 的 Godot import 閉包；來源 SHA256、匯入快取 MD5、封裝內容與實際解壓內容均需一致。BUILD-INFO 記錄來源 commit 及是否包含未提交修改。

兩次平均 FPS／P95 與記憶體變化均達門檻。第一次在計量第 426.888、428.877、429.039 秒記錄 138.479、1170.299、86.564 ms；第二次沒有超過 50 ms 的影格，故本次沒有重現超過 100 ms 的尖峰。首次停頓原因仍未確認，不能據此宣稱所有環境都不會卡頓。原始報告分別保留在 `reports/battle-soak` 與 `reports/battle-soak-repeat`。

首次每 10 秒取樣的節點低水位為 72→72；重測為 72→74，使舊自動檢查判定失敗。此數字混合常駐介面與暫時飄字／命中特效，缺少演出階段資訊，不能單靠兩個採樣值認定洩漏或放行。按場次與暫時節點分類的補測另行記錄。

補測 120.011868 秒、168 次行動、8 場戰鬥：所有 74 節點取樣都恰含一個飄字 Label 及一個命中特效 Node2D；常駐節點固定 72。8 次戰鬥結束並完成延後清理的檢查點均為 72、暫時節點為 0；完整常駐節點路徑／類別清單只記錄了初始版本，全程未變。此結果確認相同遭遇的 72／74 差異可由採樣階段重現，未見隨場次增長。已將檢查改為優先使用逐場清理後的常駐節點；舊報告的失敗旗標仍保留，不改寫歷史。短補測不取代兩次完整長測的記憶體結果。

補測平均 60.002 FPS、P95 16.728 ms、最高 27.902 ms。診斷只擴充 QA 路徑，沒有更改正常遊戲的演出或玩法。

冷啟動另計為引擎啟動至首次 `frame_post_draw`：兩次 4K 長測分別 554.485／638.341 ms；ZIP 完整解壓後的獨立啟動為 637.765 ms。不是作業系統重開機後的磁碟冷快取測試。
