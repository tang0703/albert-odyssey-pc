# V1N 索引紋理：已驗證範圍

本輪首次實作 PC 解析器，目標是 MAP001.V1N。所有整數採 big-endian。

| 相對位置 | 欄位 | 本輪接受值 |
|---|---|---|
| +0 | u16 類型 | 0x0011：8-bit 索引；0x0001：4-bit 索引 |
| +2 | u16 索引 | 同檔不可重複 |
| +4 | u16 屬性 | 僅接受 0，其他值停止 |
| +6 | u16 尺寸 | width=((value>>8)&63)*8；height=value&255 |
| +8 | 像素 | width*height*bpp/8 bytes；4-bit 先高 nibble 後低 nibble |

記錄連續排列，檔案以精確 4-byte 零結尾。尺寸高兩 bit 必須為零。
解碼後可重建每筆原始 packed bytes，並核對 SHA256。

MAP001：253 筆（128 筆 8-bit、125 筆 4-bit），包含各記錄與尾碼恰好覆蓋全檔。
已有的 `ascii_proof_page_01/VDP1_Ram.bin` SHA256
`9f0f7685f0e86aa1032a42dda1656ab841084432a0a765ac926f25e4cf74088e`
能找到其中 242 筆的完全相同 packed bytes。少於四種 byte 值的低資訊樣本不列為命中。
可重算工具為 `tools/probe_v1n.py`；它核對該獨立既有擷取雜湊後才比對。

跨檔調查：76 個 V1N 中 72 個通過同一完整結構規則。四個不支援的例外：

- MAP05D.V1N @ 0x288D0：類型 0x0021。
- MAP278.V1N @ 0x23368：屬性 0x0001。
- SPOTLH.V1N 與 TSTEFCT0.V1N：起始 0xA000 的不同格式。

不因為尺寸推算能繼續就猜測例外格式；目前全部停止並列出偏移。
