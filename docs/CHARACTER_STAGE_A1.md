# MAP001 玩家動畫 A1：來源核對驗收

日期：2026-10-09。接續基準 `e7cffb40acd635b79359b11fb0777474279d653f`。

**A1 來源核對通過。** 本階段建立可重跑的玩家動畫、來源圖像與顯示時序證據。
角色仍稱「MAP001 玩家」；目前沒有來源證據可將這個受控物件命名為派克。
A2 的任意行走家具排序與 Godot 圖像整合另行驗收；本文件不宣稱高清製作或 Windows 新版交付完成。

## 已确认的播放與圖像規則

- 四方向各有四個主要步行姿勢，每姿勢 10 次邏輯更新，一輪 40 次。
  邏輯更新間隔為 `176473 / 10546875` 秒。
- 轉向保留游標與計時；停步只重設游標，沒有無條件清除 timer。
  起步依前一狀態快取的 duration 判定，可能從第二個行走姿勢開始。
- 左右使用同組原圖，右向由已核對的鏡射旗標顯示。
  上向步行錨點為 `[16,36]`；其他待機／步行為 `[16,35]`。
  這是來源 actor 錨點，不任意改成圖片底邊。
- command 執行時讀到前一 sample 的 actor，但實際繪製內容對應前兩個 sample；
  該 framebuffer 再於下一個 video 顯示。因此已驗證 seed／路線的圖像對應三次更新前狀態。
  首段從已釘選 seed 的 framebuffer 繼承，不能冒充本次捕捉前的 command 執行紀錄。
- 原作後段的相機捲動已保留在證據中。command 建立、active scanout 與 video callback
  的相機時點分開核對；PC 仍使用固定鏡頭 `[544,1536]`，依世界座標重新投影。
- 原始圖像来自 PARTY0.PTY 的精確相同 resource 與 MAP001.TWN 色盤；PARTY2 含相同
  resource，這個別名關係不代表已識別實際 loader 路徑。Ymir 的 5-bit 色彩以左移 3 位展開。
- 背景前景由來源 pattern 的特殊優先權欄位判斷；家具遮擋由實際執行命令解釋。
  本階段沒有畫人工遮罩，也沒有把所有像素差異直接刪除。

## 回歸與界線

既有探索測試通過：移動 33,664 項、介面 991 項、場景／封裝及 QA fixture 檢查。
戰鬥核心、介面、動畫、演出時序、封裝與 QA fixture 亦通過。測試程序的 APPDATA、TEMP、
TMP 指向本地 reports 目錄；不修改全域設定。

缺少舊 `0.savestate` 的 9 項來源測試仍不能重跑；舊鎖與雜湊沒有修改。
圖像驗證範圍是玩家不透明像素及其遮擋，並非整個 Saturn 影像處理器或全畫面重建。
投影影子、場景其他動畫和未測路線不因此取得完整還原認定。

A2 必須使用來源支持的家具排序模型，才能讓任意已驗證區域行走正確遮擋；
不能把固定路線的已捕捉 draw order 當成通用規則。之後 A3 提供四方向高清造型審閱，
核准後才製作 52 張高清動畫。新素材的三解析度與 4K 效能驗收尚未開始。
