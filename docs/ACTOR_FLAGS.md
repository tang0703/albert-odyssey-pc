## 座標與狀態更新

以下偏移均相對於 TWN.BIN，其執行基址是 `0x06090000`。
呼叫位置 `0xE66E`、`0xE674` 對同一個物件指標依序呼叫 `0x1BF70`、`0x1BF18`。

`0x1BF70` 將角色 word `+0x18`、`+0x1A` 分別加到 `+0`、`+2`，寫回 16 位元結果。
兩個座標先算術右移 4 位，再 AND `0x07FF`，再除以 8。
因此查表每軸為 256 格、每格對應 128 個原始座標單位；若中間單位視為像素，
就是 1/16 像素座標與 8 像素格。此查表換算已確認，但畫面座標／鏡頭換算仍須另行核對。

對原始 unsigned 16-bit word 的等價公式：

```text
column = ((x_word >> 4) & 0x07ff) >> 3
row    = ((y_word >> 4) & 0x07ff) >> 3
address = 0x20210000 + row * 256 + column
```

查的是加上位移後的座標。這個索引公式的遮罩環繞不等於已驗證遊戲地圖允許環繞。

| 例程 | 條件 | 寫入 |
|---|---|---|
| `0x1BF70` | 表格 byte 的 bit `0x20` | 複製為角色 word `+8` 的 bit `0x02`，保留其他位元 |
| `0x1BF18` | 角色 word `+0x16` 的 bit `0x10` 為 1 | 保留高 byte；表格 `0x20` 為 0 時低 byte 改為 `0x12`，為 1 時改為 `0x13` |
| `0x1BF18` | 角色 word `+0x16` 的 bit `0x10` 為 0 | 不修改此 word |

第二個例程替換整個低 byte，並非只改其中一個 bit。
這兩個例程本身沒有阻止座標前進，不能把表格 `0x20` 當作通用障礙標記。

## 位置修正線索

`0x1B61A` 開始的另一例程讀取角色 word `+0x0A`：
零值時選擇遮罩 `0x80`，非零時選擇 `0x40`。
在 `+0x18` 位移為正的分支中，`0x1B714` 之後以 8 個中間座標單位為步長採樣表格，
`0x1B740` 測試選定遮罩。

有命中時，`0x1B75E` 起設定角色 byte `+0x4B` 的 `0x08` 及 word `+6` 的 `0x0200`，
接著從第一軸座標扣除 `(採樣座標 & 7) + 1` 的 16 倍，並清除座標低四位。
這是旗標參與位置修正的靜態證據；本輪尚未重建完整例程，也未驗證所有邊界情況。

角色 `+0x0A` 的遊戲意義、形狀表 `0x060B68DC` 的選取與各邊偏移、
負方向／第二軸修正、斜向滑動及例程的所有呼叫者仍待追蹤。
不將 `0x80`／`0x40` 簡化成一張適用所有角色的 Godot 碰撞遮罩。
