## 目的地與必要流程

- 原樓梯記錄位於 MAP001.TWN `0x1580`，提交例程 `060AC458` 寫入 scene 7、落點原始座標 `(0x3880, 0x7780)`，即 `(904,1912)`，朝下。
- TWN.BIN 場景表 `0x3057A` 指向資源 map 1／入口索引 3，再由 MAP001 指標表指向腳本 `0x1007`。目的地是 MAP001 的另一個子場景，不能將 scene 7 解讀成 MAP007 檔案或據此命名房間。
- 已載入 MAP001 第一區段 `0xF228` bytes 與來源完全一致。碰撞表於正常轉場中重新解碼，結果與原表一致；不是整份 MAP001 檔案都複製到相同 RAM 位址。
- 獨立解析來源呼叫、返回與故事位元分支，39 次初始化指令的位址、操作碼、處理函式、返回值與游標均與動態記錄相符。涵蓋資源快取、調色盤、鏡頭、三個接觸區、附加互動表、八個家具／裝飾物及 resource 50 角色。
- 九次完整流程沒有入場對話、必要確認、強制步行或連續轉場。另有音樂 id 30 請求，與轉場前保留的 id 相同；不能據此宣稱音樂播放驗收。
- 角色 50 位於 `(568,1912)`，在首次可控視窗左側之外；不能因不可見而保留舊場景角色。其初始化及後續狀態仍是新核心工作。
- 裝備後再卸下同樣可以下樓：來源判斷「曾裝備」旗標，並保留卸下後的武器槽、物品數量及攻擊值。不是強制寫成已裝備。

## 同步與顯示時序

三條正式歷程各三次完整重播，同一路線所有採樣 payload 逐檔 SHA256 相同，包含 CPU hooks、VDP 指令、RAM、framebuffer 及畫面。另從正常操作得到的具名樓梯前快照，進行三次每幀採樣的持續壓方向序列，三次亦逐檔相同。沒有修改原作 RAM。

詳細序列的相對模擬幀：

| 幀 | 來源狀態 |
|---:|---|
| 8 | 提交下樓，開始淡出；不能立即使用新場景位置 |
| 40 | RGB offset 已到 -255，但淡出狀態仍未完成 |
| 41 | 淡出完成；進行碰撞解碼及場景初始化準備 |
| 48 | 重新初始化玩家；控制鎖欄位清除，但輸入仍禁止 |
| 51–52 | 背景／鏡頭上傳；顯示座標暫為 -1 哨兵，仍全黑 |
| 53 | 新場景主迴圈開始，RGB offset 仍 -255 |
| 55 | 第一個可見目的地畫面；影像使用前一視頻幀提交的色彩 offset |
| 85 | RGB offset 到 0，淡入狀態仍未完成 |
| 86 | 淡入完成，第一次接受持續按下的方向輸入 |

來源淡入／淡出每次邏輯呼叫增減 8，限制 -255..0；完成判斷在更新前。初始化與資源上傳期間未呼叫的邏輯更新不可用視頻幀數補跑，PC 不重現 Saturn 指令執行或磁碟等待秒數。

玩家初始化由 `060A99E4`、`06094728` 及初始資源頭推導，112 bytes 全部一致。後續 61 次玩家／鏡頭更新與淡出入元件共 8,830 項比較零差異，三次重播均通過。這是元件驗證：完整跨場景排程、裝置回應、Godot 與 PC 輸入政策仍需 T2/T4 驗證。
